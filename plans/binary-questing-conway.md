# "商品理解"主题 — LLM 垂域预训练语料来源分析

## Context

基于饿了么商品理解团队的 FY26S2 规划文档，梳理文档中直接提及或隐含依赖的知识文档和数据资料，作为 LLM 补充垂域知识的预训练语料来源。

---

## 一、文档反映的核心知识领域与潜在语料来源

### 1. 品类/类目体系知识

**文档线索：** "类目/标准菜/核心CPV挂载准确率与覆盖率双≥90%"、"299类目榜单全量上线"、"爆品团类目覆盖率≥95%"

**潜在语料来源：**

| 语料 | 说明 | 价值 |
|------|------|------|
| 饿了么/口碑内部类目树 | 多级类目体系定义文档，含类目编码、父子关系、类目属性 | LLM 理解"鱼香肉丝属于川菜-家常菜"这类层级归属关系 |
| 标准菜名库 | 标准菜品名称 + 别名 + 关联类目的映射表 | 学习菜品名称的归一化能力（"宫保鸡丁" = "宫爆鸡丁"） |
| CPV（Category-Property-Value）知识库 | 品类-属性-属性值的结构化定义（如：川菜-辣度-微辣/中辣/特辣） | 学习商品属性的结构化抽取能力 |
| 行业分类标准文档 | 国标 GB/T 餐饮分类、零售商品分类（如 GPC/CPC 编码体系） | 补充行业标准视角的品类知识 |

---

### 2. 商品名称理解与改写知识

**文档线索：** "标准名称改写模型"、"套餐名称改写准确率≥95%"、"缩短超30字名称"、"品牌标品聚合"

**潜在语料来源：**

| 语料 | 说明 | 价值 |
|------|------|------|
| 名称改写 pair 对数据 | 原始商品名 → 标准化名称的平行语料（如："【超值】老王家秘制红烧肉套餐(大份+米饭+饮料)" → "红烧肉套餐"） | 学习去噪、归一化、语义保留的改写能力 |
| 商户原始菜单数据 | 商户在 Napos 上录入的原始菜品名称和描述 | 理解真实世界中商品命名的多样性和噪声模式 |
| 品牌名称知识库 | 品牌名 + 品牌别名 + 品牌所属品类 | 识别"蜜雪冰城"="蜜雪"、区分"达美乐"（品牌）和"达美乐至尊披萨"（商品） |
| 套餐结构化拆解语料 | "双人套餐A（2荤1素+米饭×2+饮料×2）" 拆解为结构化字段 | 学习套餐的组合语义理解 |

---

### 3. 卖点与推荐语知识

**文档线索：** "卖点入库率≥90%"、"时令、地域特色、节日传统小吃等事实性卖点"、"推荐语转译表达"、"用户UGC相关"

**潜在语料来源：**

| 语料 | 说明 | 价值 |
|------|------|------|
| 已入库的卖点标签数据 | 已标注的商品卖点标签（如：时令-小龙虾、地域-兰州拉面、节日-粽子） | 学习从商品信息中提取卖点的能力 |
| 用户 UGC 评论数据 | 用户对商品的评价文本 | 学习用户视角的商品认知和口语化表达 |
| 运营人工撰写的推荐语 | 运营为商品/商户撰写的推荐文案 | 学习将结构化卖点转化为吸引人的自然语言表达 |
| 数值型推荐语 → 口语化转译 pair 对 | "月售3000+" → "街坊邻居都在点"、"好评率98%" → "几乎零差评" | 学习数据到表达的转译能力 |
| 美食类内容平台语料 | 大众点评、小红书、下厨房等平台的菜品描述和推荐文本 | 补充丰富的美食领域表达和卖点描述风格 |
| 食品营养与食材知识 | 食材产地、时令季节、营养成分、烹饪特点等百科知识 | 支撑"时令卖点"、"地域特色"等事实性卖点的生成 |

---

### 4. 商品匹配与相似品知识

**文档线索：** "零售品/餐饮品匹配准确率95%"、"相似品识别"、"独家/共享品"、"品牌商品聚合重复率<15%"

**潜在语料来源：**

| 语料 | 说明 | 价值 |
|------|------|------|
| 商品匹配标注数据 | 商品A 与 商品B 是否为"同款/相似/无关"的人工标注数据 | 学习商品语义相似性的判断标准 |
| 多源异构商品描述 | 同一商品在不同商户的不同描述方式 | 理解"同物异名"场景 |
| 竞对平台商品数据 | 美团等平台的商品信息（如文档提到"独家 HD+ELE 识别"） | 学习跨平台的商品对齐与去重能力 |
| 零售行业 SKU/SPU 规范 | 标准化的商品唯一标识体系、规格描述规范 | 理解零售商品的标准化体系（条码、规格、包装单位） |

---

### 5. 套餐理解与组合知识

**文档线索：** "套餐名称改写"、"组合生成模型"、"随心配组合"、"套餐定价模型"、"高笔单套餐推荐"

**潜在语料来源：**

| 语料 | 说明 | 价值 |
|------|------|------|
| 历史套餐配置数据 | 商户已配置的套餐内容（主食+配菜+饮品组合方式、定价策略） | 学习合理的套餐组合模式 |
| 套餐采纳/拒绝记录 | 平台推荐的套餐方案被商户接受或拒绝的记录及原因 | 学习什么样的套餐组合是商户可接受的 |
| 营养搭配/膳食指南 | 中国居民膳食指南、营养搭配原则 | 支撑"合理搭配"的套餐生成 |
| 定价策略文档 | 套餐定价逻辑（单品总价 vs 套餐价的折扣率、毛利保护规则） | 理解套餐定价的商业逻辑 |

---

### 6. 供需刻画与用户需求知识

**文档线索：** "CDS需求满足度"、"人群×AOI×时段的SPU需求量"、"品宽度与品深度对转化率的边际效用"、"趋势品、场景品、刚需品"

**潜在语料来源：**

| 语料 | 说明 | 价值 |
|------|------|------|
| AOI（Area of Interest）画像数据 | 不同商圈类型（写字楼/住宅/学校）的用户行为特征 | 理解地理-需求的关联关系 |
| 时段消费分布数据 | 早餐/午餐/下午茶/晚餐/夜宵各时段的品类偏好分布 | 理解"时段×品类"的需求模式 |
| 趋势品/场景品挖掘报告 | 运营团队产出的品类趋势分析报告 | 学习什么是"趋势品"（如某季节突然爆火的品类）、"场景品"（聚餐、一人食） |
| 用户搜索 query 日志 | 用户在平台的搜索关键词 | 直接反映用户需求的表达方式和需求结构 |

---

### 7. 图灵平台与质量评估知识

**文档线索：** "商品资产质量分（Quality Score）"、"badcase反馈链路"、"准确性、完整性、时效性"

**潜在语料来源：**

| 语料 | 说明 | 价值 |
|------|------|------|
| Quality Score 评分标准文档 | 质量分的计算规则、各维度权重定义 | 理解"好的商品数据"的标准是什么 |
| Badcase 归因分析报告 | 历史 badcase 的分类、根因和修复方案 | 学习常见的商品数据质量问题模式 |
| 数据准入规则文档 | 行业数据准入的判定规则和阈值 | 理解数据质量的底线标准 |

## 二、按语料优先级排序

### P0 — 核心语料（直接决定 LLM 在该领域的基础能力）

1. **标准菜名库 + 类目树 + CPV 知识库** — 这是商品理解的骨架知识
2. **名称改写 pair 对数据** — 直接训练 LLM 的商品名称归一化能力
3. **卖点标签库 + 推荐语语料** — 训练 LLM 的卖点提取和表达生成能力
4. **商品匹配标注数据** — 训练 LLM 的语义相似性判断能力

### P1 — 重要补充语料

5. **套餐结构化数据 + 组合配置历史** — 套餐理解是高笔单场景的关键
6. **用户 UGC 评论** — 补充用户视角的商品认知
7. **商户原始菜单数据** — 理解真实世界的命名噪声
8. **用户搜索 query 日志** — 理解用户需求的表达方式

### P2 — 增强语料（提升泛化能力）

9. **外部美食内容平台语料**（大众点评、小红书、下厨房）
10. **食材/营养/烹饪百科知识**
11. **行业分类标准文档**（国标等）
12. **AOI 画像 + 时段消费分布数据**

## 三、语料使用方式建议

| 阶段 | 语料类型 | 目的 |
|------|---------|------|
| Continue Pre-training | 类目体系、菜品百科、食材知识、美食内容平台文本 | 注入领域通识知识 |
| Supervised Fine-tuning | 名称改写 pair 对、卖点提取标注、匹配标注、推荐语转译 pair 对 | 学习特定任务能力 |
| Preference Alignment (DPO/RLHF) | 套餐采纳/拒绝记录、badcase 归因、推荐语 A/B test 结果 | 对齐业务偏好 |
